# M1 검증 기록

- 환경: macOS 14.5 Intel, Go 1.27.4, OSV-Scanner 2.7.1. 도구는 공식 배포물 SHA-256 확인 후 로컬 캐시에 설치했다.
- DB: M0의 npm 스냅샷과 동일. M0 평가 정답은 제품 바이너리에 포함하지 않는다. acceptance.py에서 제품 설정과 M0 핀 일치를 검사한다.
- 실제 CLI로 실행한 결과:

| 입력 | 상태 | 종료 | 공지 |
|---|---|---:|---:|
| lodash 4.17.20 | complete | 1 | 4, 기준 GHSA 포함 |
| lodash 4.17.21 | complete | 1 | 2, 기준 GHSA 제외 |
| is-number 7.0.0 | complete | 0 | 0 |
| 지원 파일 없는 디렉터리 | unsupported | 2 | 미검사 |
| DB 없는 캐시 | failed | 2 | 미검사 |
| is-number + 로컬 링크 | partial | 2 | 0, 한 항목 제외 |

- 사용한 macOS 프로필로 루프백 소켓 바인딩과 임시 파일 생성을 각각 시도해 둘 다 권한 거부를 확인했다. 같은 프로필에서 실제 스캐너가 OSV DB를 읽고 결과를 출력했다.
- 단위 검사에서 중첩 패키지와 alias의 동일 좌표 중복 제거, 로컬·사설 레지스트리·범위 버전 제외, 미지원 lockfile 형식 거부를 확인했다.
- Linux 격리 경로의 실제 실행 검증은 남아 있다. 이 기록은 소스 코드 분석이나 프로젝트 전체 취약점 부재를 증명하지 않는다.

## M1 계층 분리 후 판정 계약

CLI가 M1 보고서와 종료 코드를 소유한다. internal/osv는 지원 입력 판정, 버전·DB 검증, 실행 인자와 캐시 환경, OSV 결과 해석을 담당한다. internal/runner는 도구별 인자와 환경을 받아 격리된 프로세스를 실행한다. 어댑터 결과에는 예상 패키지 수, 검사한 수, 제외 수와 검증된 발견이 들어간다.

예상하지 않은 패키지, 공지 ID 누락 또는 OSV 종료 코드와 발견 수의 모순은 응답 전체를 무효화한다. 이때 CLI는 failed로 표시하고 검증되지 않은 발견을 내보내지 않는다. 유효하게 해석한 응답에서 예상 패키지 일부만 누락되었다면 partial로 표시하고 검증된 발견은 유지한다.
